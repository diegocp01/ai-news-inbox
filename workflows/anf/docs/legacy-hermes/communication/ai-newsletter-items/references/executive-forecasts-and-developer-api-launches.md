# Executive forecasts and developer API launches

## Executive AGI forecasts

- Locate the original interview or transcript and quote the operative wording, including whether the prediction concerns an **internal system**, a public release, or a demonstrated achievement.
- Treat AGI as definition-dependent. Record the speaker/company definition and distinguish it from broader scientific or public meanings.
- Separate these states explicitly: “not there yet,” forecast by a date, internal milestone, public availability, and independently verified achievement.
- Preserve attribution. A CEO saying they expect a system they would call AGI is a forecast, not evidence that AGI has been achieved.
- If a secondary headline omits qualifiers such as “internal” or “under our definition,” restore them in the neutral title and summary.

## Developer chat-agent and bot API launches

- Verify the bot’s identity and control model: project-owned versus user-owned account, passwordless versus login-capable, token type, token rotation/revocation, and ownership labeling.
- Verify supported operations from live API docs: direct messages, groups, media, typing/read state, real-time events, and encryption-key handling. Do not imply autonomous reasoning merely because the product uses “agent” branding.
- Distinguish a programmable messaging bot account from a supplied AI model or hosted agent runtime. State only the agentic behavior the announcement or docs establish.
- If the only exact launch page is on a policy-blocked social or documentation domain, use it as verification evidence but leave `URL:` blank unless compliant same-event coverage exists.
- Generic brand logos are acceptable only as last-resort imagery after searching for a compliant launch-specific visual; verify the direct asset URL and dimensions.

## Model architecture and hardware claims

- For mixture-of-experts releases, report total parameters and active parameters separately.
- Distinguish native multimodal input support from speech-to-text or other narrower modality claims.
- Separate training hardware from inference/serving hardware. “Served entirely on domestic chips” does not establish that the model was trained on those chips.
- Preserve preview versus general-availability wording and distinguish model weights, hosted API access, coding subscriptions, and chat products as separate release surfaces.
